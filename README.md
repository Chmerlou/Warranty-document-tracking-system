# Система учета гарантийных документов

Веб-приложение на Django и сохраненная консольная версия для централизованного
учета гарантийных документов, контроля сроков и просмотра связанных сведений о
товарах, клиентах и продавцах.

## Назначение

Приложение заменяет бумажный и разрозненный учет гарантийных документов
единой электронной базой. Оно позволяет хранить несколько документов,
контролировать сроки гарантии, искать и сортировать записи, а также получать
уведомления о скором окончании гарантийного срока.

## Целевая аудитория

- сотрудники сервисных центров и магазинов;
- менеджеры по гарантии;
- администраторы системы;
- клиенты, которые в перспективе смогут просматривать свои гарантии.

## Предметная область

Предметная область охватывает регистрацию товара, клиента, продавца и
подтверждающего гарантию документа. Для документа учитываются дата начала,
продолжительность и дата окончания гарантии.

## Основные сущности

- **WarrantyDocument** — гарантийный документ со сроком действия.
- **Client** — владелец товара и гарантийного документа.
- **Product** — товар, на который распространяется гарантия.
- **Seller** — организация, продавшая товар.
- **Party** — общий базовый класс клиента и продавца.
- **Пользователь** — будущая учетная запись сотрудника системы.
- **Сервисное обращение** — будущая запись о гарантийном обслуживании.
- **Категория товара** — будущий классификатор товаров.

## Возможности

- главная веб-страница со сводкой по реальным данным;
- веб-реестр гарантийных документов;
- страницы отдельных документов по динамическим URL;
- веб-список клиентов и страницы их гарантий;
- поиск документов по номеру, товару, клиенту или продавцу;
- веб-статистика по статусам гарантий и клиентам;
- реляционная база данных SQLite и SQL-запросы;
- Django Template Language, наследование шаблонов и переиспользуемые
  компоненты;
- единая навигация, адаптивное оформление, Bootstrap 5.3 и собственный CSS;
- локальный логотип и JavaScript для автоматического вывода текущего года;
- собственные страницы для неизвестного URL и отсутствующего объекта;
- просмотр всех гарантийных документов;
- добавление и удаление документов;
- расчет даты окончания и текущего статуса гарантии;
- поиск по номеру документа, клиенту, товару и продавцу;
- фильтрация документов по статусу гарантии;
- поиск гарантий, истекающих в течение 30 дней;
- сортировка документов по дате окончания;
- сохранение объектов в JSON и восстановление объектов при запуске;
- поддержка загрузки JSON-данных, созданных в ПР2;
- защита от некорректного пользовательского ввода и ошибок файлов.

## Веб-интерфейс

В ПР5 к существующему проекту добавлен Django 5.2, в ПР6 интерфейс переведен
на Django Template Language, а в ПР7 веб-слой подключен к SQLite через модуль
`sqlite3`. Django ORM на текущем этапе не применяется.

Основные страницы:

- `/` - главная страница и сводка;
- `/warranties/` - список гарантийных документов;
- `/warranties/search/` - параметризованный поиск по реестру;
- `/warranties/statistics/` - агрегированная статистика;
- `/warranties/<id>/` - карточка выбранного документа;
- `/clients/` - список клиентов;
- `/clients/<id>/` - профиль клиента и его гарантии;
- неизвестный адрес - оформленная страница с кодом HTTP 404.

View-функции выполняют SQL-запросы, получают именованные строки
`sqlite3.Row`, подготавливают словарь контекста и вызывают `render()`.
HTML-строки в Python-коде не формируются, функция `page()` больше не
используется.

## Django Template Language

Общий каркас интерфейса находится в `templates/base.html`. Он подключает
Bootstrap, собственные статические файлы, общую навигацию и определяет блоки
`title` и `content`. Шаблоны пяти основных страниц наследуют этот каркас через
`{% extends "base.html" %}` и заполняют его блоки.

Повторяющиеся фрагменты вынесены в подключаемые шаблоны:

- `templates/includes/navigation.html` - основная навигация;
- `warranties/includes/warranty_card.html` - карточка документа;
- `warranties/includes/warranty_status.html` - статус гарантии;
- `clients/includes/client_card.html` - карточка клиента.

Данные передаются из view-функций через контекст. В шаблонах используются
циклы `{% for %}`, ветвления `{% if %}`, обработка пустых коллекций
`{% empty %}`, а также фильтры `length`, `default` и `date`.

Все внутренние ссылки формируются тегом `{% url %}` по именованным маршрутам
и пространствам имен `homepage`, `warranties` и `clients`. Жестко заданные
адреса для переходов между страницами не используются.

## Статические файлы

Собственные ресурсы находятся в `homepage/static/homepage/`:

- `css/style.css` содержит адаптивное оформление, состояния фокуса и темную
  цветовую схему;
- `img/logo.svg` используется в общей шапке сайта;
- `js/main.js` автоматически выводит текущий год в подвале.

Ресурсы подключаются в `base.html` через `{% load static %}` и тег
`{% static %}`. Bootstrap сохранен для базовых вспомогательных классов, при
этом внешний вид основных компонентов определяется собственным CSS проекта.

## База данных SQLite

В ПР7 добавлен отдельный реляционный слой без Django ORM. Файл базы находится
в `data/warranty_tracker.sqlite`, схема хранится в `sql/schema.sql`, а
подключение выполняется модулем `db/database.py`.

Структура базы данных:

- `clients`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`;
- `products`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`;
- `sellers`: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`;
- `warranty_documents`: идентификатор, уникальный номер документа, внешние
  ключи клиента, товара и продавца, даты начала и окончания, срок гарантии.

Таблица `warranty_documents` связана внешними ключами:

- `client_id` ссылается на `clients.id`;
- `product_id` ссылается на `products.id`;
- `seller_id` ссылается на `sellers.id`.

При каждом подключении выполняется `PRAGMA foreign_keys = ON`, а
`sqlite3.Row` позволяет обращаться к столбцам результата по именам.

### Перенос данных из JSON

Исходные данные ПР1-ПР6 сохранены в `data/warranty_documents.json`. Для
создания таблиц и повторяемого переноса данных используется команда:

```bash
python -m db.import_json
```

Скрипт `db/import_json.py` применяет SQL-схему, загружает существующие
предметные объекты, вставляет связанные записи через `executemany()` и
фиксирует изменения одной транзакцией. При ошибке выполняется `rollback()`.

### SQL-запросы

Файл `sql/queries.sql` содержит 14 проверенных запросов. В них используются:

- выборка, сортировка, `LIMIT`;
- фильтрация `WHERE`, `LIKE` и `BETWEEN`;
- соединения `JOIN` и `LEFT JOIN`;
- агрегаты `COUNT`, `AVG`, `MIN` и `MAX`;
- группировка `GROUP BY`;
- фильтрация групп `HAVING`.

Пользовательские значения в Django передаются заполнителями `?`. Поиск и
детальные страницы не используют конкатенацию или f-строки для подстановки
введенных данных.

## Объектная модель

`WarrantyDocument` хранит ссылки на объекты `Client`, `Product` и `Seller`.
Таким образом, документ связывает участников и товар внутри предметной области,
а не содержит разрозненные словари с их данными.

В проекте применены основные принципы ООП:

- **инкапсуляция** — внутренние атрибуты объектов защищены префиксом `_`,
  чтение выполняется через properties;
- **наследование** — `Client` и `Seller` наследуются от `Party`;
- **полиморфизм** — классы переопределяют `role_name()`, а базовая реализация
  `__str__()` формирует представление с учетом фактической роли объекта;
- **абстракция поведения** — расчет статуса, срока и уведомления находится в
  методах `WarrantyDocument`.

## Основные функции и методы

Методы объекта `WarrantyDocument`:

- `get_status()` определяет статус гарантии;
- `days_until_expiration()` вычисляет число оставшихся дней;
- `get_expiration_notice()` формирует уведомление;
- `expires_within()` проверяет окончание гарантии в заданный период;
- `matches()` проверяет совпадение с поисковым запросом;
- `to_dict()` и `from_dict()` преобразуют объект в JSON-данные и обратно;
- `__str__()` формирует удобное строковое представление.

Функции обработки коллекций:

- `create_warranty_document()` создает связанные объекты и документ;
- `find_warranty_documents()` выполняет поиск объектов;
- `filter_documents_by_status()` фильтрует документы по статусу;
- `filter_expiring_documents()` находит скоро истекающие гарантии;
- `sort_warranty_documents()` сортирует коллекцию объектов;
- `delete_warranty_document()` удаляет документ из коллекции;
- `load_documents()` и `save_documents()` работают с JSON-хранилищем.

Функции расчета из ПР1 и функциональность ПР2 сохранены. Расчеты делегируются
объектной модели, чтобы логика не дублировалась.

## Назначение модулей

### `warranty_tracker/`

Пакет конфигурации Django: настройки проекта, корневые маршруты, WSGI и ASGI.

### `homepage/`

Django-приложение главной страницы. Содержит ее шаблон, собственные CSS,
JavaScript и логотип. Представления подготавливают сводные данные и обработчик
ошибки 404.

### `warranties/`

Django-приложение списка, поиска, статистики и детальных страниц гарантийных
документов. Представления получают данные SQL-запросами из SQLite.

### `clients/`

Django-приложение списка клиентов и страниц связанных гарантий. Данные
получаются через `JOIN`, `LEFT JOIN`, `WHERE` и `GROUP BY`.

### `db/`

Содержит подключение к SQLite, общий SQL-фрагмент получения документов и
скрипт переноса исходных JSON-данных.

### `sql/`

Содержит воспроизводимую схему таблиц и набор проверенных запросов предметной
области.

### `templates/`

Общие Django-шаблоны: базовая HTML-структура, навигация, страница 404 и
представление ошибки загрузки данных.

### `main.py`

Точка входа в приложение. Отвечает за запуск, отображение меню, получение
данных от пользователя и организацию пользовательских сценариев.

### `models/`

Пакет объектной модели. Содержит классы гарантийного документа, клиента,
товара и продавца, а также общий базовый класс участников.

### `warranty_documents.py`

Содержит функции создания, поиска, фильтрации, сортировки, удаления и вывода
коллекции объектов `WarrantyDocument`.

### `storage.py`

Отвечает за загрузку и сохранение данных. Преобразует JSON в объекты Python,
а объекты Python — в JSON-совместимые словари.

### `utils.py`

Содержит вспомогательные функции безопасного ввода строки, целого числа и
даты.

### `tests/`

Содержит автоматизированные тесты классов, методов, функций коллекций и
JSON-хранилища.

## Требования

- Python 3.11 или новее;
- Django 5.2;
- SQLite 3 и стандартный модуль Python `sqlite3`;
- pytest;
- flake8.

Установка зависимостей:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Запуск веб-приложения

```bash
python manage.py runserver
```

После запуска откройте `http://127.0.0.1:8000/`.

Проверка конфигурации Django:

```bash
python manage.py check
```

Если база данных отсутствует или требуется повторно перенести исходные данные:

```bash
python -m db.import_json
```

## Запуск консольной программы

```bash
python main.py
```

После запуска отображается главное меню. Все изменения сохраняются в
`data/warranty_documents.json` при выборе пункта выхода.
